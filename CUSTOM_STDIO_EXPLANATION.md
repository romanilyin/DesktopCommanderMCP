# Stdio-транспорт SGG Local MCP

Реализация: [src/custom-stdio.ts](src/custom-stdio.ts), подключение: [src/index.ts](src/index.ts), общий logger: [src/utils/logger.ts](src/utils/logger.ts).

## Поток сообщений

`FilteredStdioServerTransport` оборачивает стандартный stdio-транспорт MCP SDK. При создании он сохраняет исходные console/stdout функции, затем перехватывает console-сообщения и строковые записи stdout. Служебные сообщения до завершения handshake помещаются в память. После `server.oninitialized` вызывается `enableNotifications()`, и разрешённые сообщения передаются подключённому MCP-клиенту как `notifications/message`.

Строки stdout, похожие на JSON-RPC, пропускаются без изменений. Остальной непустой строковый вывод преобразуется в log notification. Проверка выполняется по форме строки, а не полноценной валидацией протокола; Buffer-записи проходят напрямую. Поэтому прикладной код должен пользоваться SDK и logger, а не писать произвольные данные в stdout.

## Поведение для клиентов

`configureForClient()` вызывается до включения уведомлений. Для имени клиента, содержащего `cline` или `vscode`, а также для `claude-dev`, log notifications отключаются. В таком режиме накопленный буфер очищается, а stderr получает краткое сообщение о подавлении. Это существующее правило совместимости транспорта; оно не определяет, как другие версии клиентов отображают собственные журналы.

Остальным клиентам разрешены protocol log notifications после инициализации. Они идут по текущему MCP-соединению. Внешнего канала продуктовой аналитики у транспорта нет. В логах не следует размещать ключи, токены и необязательное содержимое пользовательских файлов.

## Размеры ответов и жизненный цикл

Для запуска через `local/start-local.mjs` дополнительно устанавливается [response guard](local/response-guard.mjs), который ограничивает размеры SDK-ответов для Secure MCP Tunnel. Прямые записи в stdout обходят этот guard. При усечённом результате изменяющей операции сначала прочитайте уже созданный результат частями: повтор вызова может повторить само изменение.

Метод `cleanup()` транспорта восстанавливает исходные console/stdout функции. Локальные smoke и integration tests проверяют handshake и вызовы инструментов; изменение логирования также должно сохранять возможность разобрать stdout как поток MCP-сообщений.
