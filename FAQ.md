# SGG Local MCP: частые вопросы

## Где взять сервер?

Клонировать [этот репозиторий](https://github.com/romanilyin/DesktopCommanderMCP) и собрать код. Основной путь Windows-установки описан в [инструкции](docs/local-mcp-windows.ru.md). npm-пакет `@romanilyin/sgg-local-mcp` помечен `private: true`; публикация в npm не выполняется.

## Отправляет ли сервер телеметрию?

Продуктовая телеметрия, удалённая конфигурация экспериментов, установочная аналитика и UI-tracking удалены. Настройка не может включить отсутствующий sender. `get_usage_stats`, история вызовов и диагностические журналы работают локально; [PRIVACY.md](PRIVACY.md) описывает их назначение и сетевые функции.

## Нужен ли облачный сервис разработчика сервера?

Для прямого stdio-подключения — нет. Windows-развёртывание для ChatGPT использует настроенный пользователем private OpenAI Secure MCP Tunnel. У каждого компьютера собственные runtime key и профиль. Общий облачный relay исходного проекта не используется.

## Работает ли сервер совсем без интернета?

Локальные файлы, поиск и процессы могут работать без сети после установки зависимостей. Чтение URL, импорт изображений из ChatGPT и подключение Secure Tunnel требуют сети. Сборка загружает зависимости; создание PDF может потребовать доступный Chrome/Chromium. Команды терминала и содержимое документов также могут обращаться к сети по своему назначению.

## Почему осталось имя `desktop-commander`?

Это совместимый CLI-alias, чтобы существующие запускающие конфигурации продолжали работать. Основное имя продукта — SGG Local MCP, CLI — `sgg-local-mcp`. Имена существующих задач, туннелей и каталоги пользовательского состояния не переименовываются автоматически.

## Как отключить карточки файлов?

Задайте `set_config_value` с `key: "mcpUiPreviewsEnabled"` и `value: false`. Для возврата превью используйте `true`. Обновите список инструментов в клиенте после изменения; уже показанные карточки могут остаться в истории чата.

## Какой PowerShell поддерживается на Windows?

Локальная инфраструктура использует PowerShell 7/Core (`pwsh.exe`). Установщик и сборка проверяют окружение. Windows PowerShell 5.1 для этих скриптов не подходит.

## Почему обновление клона не обновило работающий сервер?

Уже запущенный Node-процесс продолжает использовать загруженный код, а установленный runtime может работать из отдельного каталога версии. Пересоберите и перезапустите свой экземпляр по [инструкции восстановления](docs/local-recovery.ru.md). Не останавливайте другие процессы Node или чужие туннели.

## Где лежат ключи и журналы?

Инфраструктура конкретного checkout хранится в игнорируемом `.local/`. Runtime key защищается Windows DPAPI текущего пользователя. MCP-конфигурация и локальная история могут использовать совместимые пользовательские каталоги предыдущих версий. Не публикуйте `.local`, конфигурации, историю вызовов и журналы с пользовательскими данными.

## Можно ли нескольким чатам работать на одном ПК?

Да, но файловая система, запущенные процессы и часть состояния общие. Туннель не превращает чаты в отдельные песочницы. Для параллельной работы используйте разные рабочие каталоги и согласованный доступ к изменяемым файлам.

## Где сообщить о проблеме?

В [issues этого репозитория](https://github.com/romanilyin/DesktopCommanderMCP/issues). Укажите commit SHA, ОС, Node.js, PowerShell и шаги воспроизведения. Удалите из приложенных журналов ключи, токены, private URLs и чувствительные данные.
