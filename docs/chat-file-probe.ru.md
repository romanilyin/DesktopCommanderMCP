# Проверка передачи файлов ChatGPT: подготовленный этап A

Статус на 29.09.2026: подготовлен отдельный MCP для проверки файлового входа и очистка аргументов будущих инструментов в журнале Desktop Commander. **Импорт на диск ещё не реализован. Получение настоящего вложения или сгенерированного изображения от ChatGPT через Tunnel ещё не проверено.** Синтетический тест SDK подтверждает только локальную обработку контракта.

Эта работа следует [плану передачи файлов](chat-file-import-plan.ru.md): сначала подтвердить источник байтов, затем реализовать загрузку и сохранение. Тестовый код можно подготовить без изменения работающего MCP. Для использования новых инструментов в существующем запущенном сервере потребуется загрузка новой версии и обновление списка инструментов в ChatGPT; это отложено до остановки работы чатов пользователем. Альтернатива — отдельное тестовое подключение, которое не заменяет рабочий туннель.

## Что подготовлено

- `local/chat-file-probe.mjs` — самостоятельный stdio MCP с одним инструментом `inspect_chat_file_source`. Он не импортирует основной сервер, не читает его конфигурацию и не подключается к его процессам.
- Инструмент объявляет `openai/fileParams` и ожидает реальный файловый объект от клиента. Он сообщает только наличие полей, hostname источника, признак стандартного HTTPS-порта и распознанный из заявления MIME PNG/JPEG/WebP. Путь URL, query, fragment, file_id и имя файла в ответ не попадают.
- Пробник не делает сетевых запросов, не скачивает и не записывает файлы. `download_checked: false` и `file_saved: false` явно присутствуют в результате. Возвращённый hostname ещё не означает, что адрес разрешён или доступен для будущего скачивания.
- `src/utils/sanitize-tool-arguments.ts` очищает аргументы `inspect_chat_file_source` и будущего `import_chat_file` перед журналированием и сохранением истории. Сохраняются лишь фиксированные признаки наличия полей; сырые значения и неизвестные дополнительные поля не сериализуются.
- Функции записи и чтения, запущенные процессы, Windows-задачи и конфигурация рабочего Tunnel на этом этапе не меняются.

## Локальные проверки

Из корня клона, используя установленный Node.js:

```powershell
$cfg = Get-Content ./.local/config.json -Raw | ConvertFrom-Json
& $cfg.nodePath ./node_modules/typescript/bin/tsc --pretty false --listEmittedFiles false --diagnostics false --extendedDiagnostics false
& $cfg.nodePath --test local/test/chat-file-probe.test.mjs local/test/chat-file-redaction.test.mjs
```

Проверки используют синтетические URL на example.com и секретные маркеры. Они проверяют схему, optional-поля, фиксированные ошибки без утечек, stdio discovery, историю в изолированном профиле и отсутствие исходных аргументов в тестовых журналах. Пробник не требует отдельной сборки; компиляция нужна для тестов изменений TypeScript-журналирования.

Эти результаты нельзя считать доказательством поддержки сгенерированных изображений клиентом ChatGPT. Тесты не вызывали рабочие MCP-инструменты и не проверяли активный туннель пробной записью.

## Следующий шаг: реальное тестовое подключение

Предпочтительный вариант при продолжающейся работе чатов — новый тестовый Tunnel с отдельным alias, профилем, состоянием и разрешённым runtime-ключом. Подключить к нему отдельный тестовый плагин в ChatGPT. Не использовать alias, health-file, PID-файлы или рабочую задачу Desktop Commander Local для второго процесса. Не копировать секреты в репозиторий и не публиковать их.

Команда stdio для такого отдельного подключения:

```text
"<absolute path to node.exe>" "<absolute clone path>/local/chat-file-probe.mjs"
```

В тестовом чате выполнить два отдельных сценария:

1. Прикрепить небольшой PNG и попросить передать именно это вложение в `inspect_chat_file_source`.
2. Создать изображение в ChatGPT и попросить передать именно сгенерированный файл в тот же инструмент.

Не подставлять вручную придуманный file_id или URL: это проверило бы только сервер и скрыло бы отсутствие выдачи файла клиентом. Не считать картинку, повторно загруженную пользователем, прямой передачей из генерации.

Сохранить в отчёт только поверхность ChatGPT, тип сценария, дату, факт вызова, имена присутствующих полей и hostname без URL. Если клиент не передаёт объект, зафиксировать ограничение и проверить явный выбор/прикрепление файла.

После подтверждения файлового объекта отдельно проверить скачивание оригинальных байтов с верифицированного хоста ограниченным тестовым загрузчиком. Этот шаг ещё предстоит: текущий пробник не доказывает сетевую доступность или валидность ссылки. Затем переходить к основной реализации по плану.

## Состояние выпуска

Пробник не добавлен в список инструментов рабочего Desktop Commander и не зарегистрирован в ChatGPT автоматически. Запущенный релиз не заменён. Очистка журналирования находится в исходниках и станет активной только в процессе, запущенном из новой сборки; для самостоятельного пробника журналы аргументов вообще не ведутся.

Обновление действующего подключения выполнять только в согласованное окно: сохранить состояния незавершённых терминальных сессий, проверить новый артефакт, остановить чаты, перезапустить MCP и обновить discovery. До разрешения пользователя не переключать текущий Tunnel даже на временный пробник.
