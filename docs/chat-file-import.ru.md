# Импорт изображений из ChatGPT

## Причина прежнего отказа

В сборке `49b3f4f` инструмент `inspect_chat_file_source` выполнял только проверку
дескриптора. В нём отсутствовали HTTP-загрузка и запись файла. Поля
`download_checked: false`, `file_saved: false` были штатным результатом пробника,
а не доказательством ошибки передачи вложения или регрессии модели.

1 октября 2026 на STINGER-SPB-PC подтверждена передача настоящего сгенерированного
изображения из локального Codex в пробник: клиент передал все четыре файловых
поля, источник — `sdmntprdenmarkeast.oaiusercontent.com`. Автоматическое локальное
сохранение Codex и последующее чтение PNG через MCP проверены отдельно. Это не
проверка скачивания сервером и не доказательство поведения веб-интерфейса ChatGPT.

## Исправление

Добавлены два инструмента:

- `import_chat_file(file, destination_path, transfer_id)` скачивает оригинал PNG,
  JPEG или WebP и создаёт новый файл в существующем разрешённом каталоге.
- `get_chat_file_transfer(transfer_id)` читает устойчивую квитанцию и проверяет
  сохранённый файл по размеру и SHA-256, без сетевого запроса и повторной записи.

Пробник остаётся доступен, но теперь указывает на инструмент импорта.
Файловый параметр объявлен по [официальному контракту OpenAI](https://developers.openai.com/plugins/reference#file-apis):
`_meta["openai/fileParams"] = ["file"]`, обязательные `download_url`, `file_id`,
необязательные `mime_type`, `file_name`.

Пример запроса в чате с подключённым **Desktop Commander Local**:

> Сохрани эту сгенерированную картинку на STINGER-SPB-PC через import_chat_file
> в C:\Temp\stinger-chat-image-test.png. Используй уникальный transfer_id.
> При обрыве сначала проверь get_chat_file_transfer с тем же ID.

Выбирать надо реальный файл средствами клиента. Не следует придумывать file_id,
ссылку, использовать путь sandbox как путь Windows или пересылать base64 текстом.
Выбор другого коннектора означает другой компьютер.

## Ограничения и повторы

- Один файл до 25 MiB, загрузка и проверка ограничены 45 секундами; до двух операций
  одновременно в одном процессе. Изображения до 64 мегапикселей, без многостраничных
  и анимированных контейнеров. Новых зависимостей нет.
- HTTPS только на поддоменах `oaiusercontent.com` и на точном адресе
  `oaisdmntprdenmarkeast.blob.core.windows.net`, который был подтверждён реальным
  файловым пробником из веб-ChatGPT. Произвольные Azure storage accounts запрещены.
  Это локальная политика первого выпуска, не обещание полного перечня
  CDN OpenAI. Каждый redirect повторно проверяется; DNS должен разрешаться только
  в публичные адреса, подключение закрепляется за проверенным IP с обычной TLS-проверкой.
  Ключи, cookies и прокси-учётные данные не передаются.
- При 401/403/404/410 возвращается `SOURCE_UNAVAILABLE`: нужно заново выбрать файл
  в клиенте. Один HTTP-код не доказывает, что ссылка именно истекла.
- Родитель назначения должен существовать и проходить действующую allowedDirectories.
  UNC/device paths, ADS, неоднозначные Windows-имена и неподдерживаемые расширения
  отклоняются. Права и конфигурация сервера не расширяются.
- Запись идёт в отдельный временный файл; проверка изображения не перекодирует его.
  Публикация через hard link атомарно отказывает при занятом имени. Файловая система
  должна поддерживать hard links; небезопасного fallback через перезаписывающий rename нет.
- Квитанции хранятся в `.claude-server-commander/chat-file-transfers` домашнего каталога
  runtime. В них нет URL, file_id, имени источника или содержимого. Связь файла и пути
  записывается только SHA-256 отпечатком. В историю MCP аргументы попадают очищенными.
- Повтор того же ID с тем же файлом и путём не скачивает данные второй раз. Изменение
  файла/пути с прежним ID — `TRANSFER_ID_CONFLICT`. `saved`/`already_saved` подтверждают
  размер и SHA-256. Если файл после записи изменился, результат — `needs_verification`.
- После потерянного ответа сначала запросить статус. `in_progress` означает текущую
  операцию. `needs_verification` — недостаточно данных после прерывания, автоматической
  повторной записи нет. `failed` — операция завершилась ошибкой: после проверки пути
  и устранения причины нужен новый ID. `unknown` — квитанции нет; само по себе это не
  подтверждает, что предыдущий вызов не доставлен.
- При нормальной ошибке временный файл удаляется. После аварийного завершения процесса
  он может остаться с префиксом `.codex-chat-import-`; автоматического удаления чужих
  или старых файлов не выполняется. Проверки канонического родителя сокращают риск
  подмены пути; против привилегированного локального процесса, одновременно меняющего
  каталоги, полной транзакционной изоляции средствами Node path API нет.

## Проверка и установка на STINGER

Исправление подготовлено отдельно от работающей сборки. TypeScript и целевые тесты
проверяют сохранение исходных байтов, прозрачность, JPEG/WebP, подмену/исчезновение
результата, параллельные вызовы, восстановление после перезапуска, ограничения URL/DNS,
таймаут чтения body, повреждённые изображения, отсутствие перезаписи и утечек URL.
Сетевые отказы воспроизводятся имитацией HTTPS/DNS; это не подмена живого E2E-теста.

2 октября 2026 (МСК) на STINGER установлена сборка
`49b3f4f-chat-import-20261002-r2`. TypeScript и 27 целевых тестов прошли как в рабочем
клоне, так и в подготовленной установленной копии на Node 24. В ChatGPT обновлён
список инструментов; сохранены существующие ключи и права, пассивный монитор работает.

Настоящий PNG был создан в исходном локальном чате и повторно прикреплён к веб-ChatGPT.
Нативная генерация в выбранном веб-сеансе была недоступна, поэтому именно этот этап
не считается проверенным. Первый импорт отклонил источник; отдельный успешный
файловый пробник выявил Azure-hostname, отсутствовавший в первоначальной политике.
После добавления точного адреса вызовы `import_chat_file` и `get_chat_file_transfer`
вернули `saved`. Сохранённый файл независимо прочитан и проверен на диске.

При прикреплении ChatGPT изменил кодирование PNG. Поэтому проверены обе границы:

| Проверяемый файл | Размер, байт | SHA-256 |
| --- | ---: | --- |
| Исходная локально сгенерированная PNG | 1 505 762 | `c7943a76e4333a87a0ce97e0f20b5f7994ff3505c4ab6f68f54388dc6ef6e3d6` |
| Вложение, отдельно полученное из ChatGPT | 2 390 216 | `3d2dabcaa6f24a012d79806d53c6203988403929bed539977deff8f9ab952a8c` |
| Файл, сохранённый приватным MCP | 2 390 216 | `3d2dabcaa6f24a012d79806d53c6203988403929bed539977deff8f9ab952a8c` |

У всех трёх вариантов размер изображения 1254×1254; SHA-256 декодированных пикселей
RGBA/sRGB совпадает: `33d4b0b6a2dcd89542599a0cb4be2e26d4cac10be3777231debdd011dafb9a54`.
Таким образом, MCP сохранил точные байты файлового источника ChatGPT, а изменение
PNG-контейнера произошло до импорта и в этом тесте не изменило пиксели. Для следующих
проверок сравнивать байты следует с фактическим вложением ChatGPT; совпадение с файлом
до загрузки зависит от обработки самим клиентом. Ни изображение, ни временные URL,
идентификаторы файлов, квитанции или локальные журналы в репозиторий не включаются.

UshinePCVrn не изменялся и не проверялся.
